Medium main aws_vpc TMAC-AWS-VPC-001 Repudiation examples/demo/main.tf

Rule Definition: Amazon VPC without Flow Logs Enabled

An AWS VPC is being defined without network-level traceability (Flow Logs). By not capturing information about the IP traffic entering and leaving the network interfaces, there is no visibility into network scans, anomalous traffic or intrusions (Repudiation). IMPLEMENTATION NOTE: This rule uses a tag-based workaround because the TMAC v1.0.0 engine does not correlate distinct resources. If you already declared an aws_flow_log resource associated with this VPC, add the 'FlowLogs = "enabled"' tag to suppress this finding. See DOCS/aws_stride_mapping.md for full documentation of the limitation.

Violation Trigger

Matched attribute: tags.FlowLogs

Recommended Mitigation

Create an 'aws_flow_log' resource associated with this VPC and add the 'FlowLogs = "enabled"' tag to indicate to TMAC that Flow Logs are active: resource "aws_vpc" "main" { cidr_block = "10.0.0.0/16" tags = { FlowLogs = "enabled" } } resource "aws_flow_log" "main" { vpc_id = aws_vpc.main.id traffic_type = "ALL" iam_role_arn = aws_iam_role.flow_log.arn log_destination = aws_cloudwatch_log_group.flow_log.arn }

References

  • https://docs.aws.amazon.com/vpc/latest/userguide/flow-logs.html
  • CIS AWS Benchmark v2.0.0 - 4.3

Rule Definition: SSH Port (22) Open to the World

The SSH port (22) is globally exposed (0.0.0.0/0), enabling brute-force attacks, exploitation of SSH service vulnerabilities, and unauthorized access to instances.

Violation Trigger

Matched attribute: ingress.from_port

Recommended Mitigation

Restrict SSH access to known corporate IPs only, or use AWS Systems Manager Session Manager as an alternative with no open ports: ingress { from_port = 22 to_port = 22 protocol = "tcp" cidr_blocks = ["10.0.0.0/8"] # Corporate network only }
